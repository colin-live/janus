
# 相对原规范 v1.0 的修订说明

| # | 原规范 | 修订 | 原因 |
|---|---|---|---|
| 1 | 作用量含弹簧/阻尼/摩擦/接触力等多类 | 仅保留 joint_torque、joint_force、body_force、body_torque（热功率留作扩展域） | 其余都是模型内部如何算出力的区别，交换层只关心力/力矩 |
| 2 | 状态量含加速度、动量、角动量 | 第一版移除 | Webots 无直接接口 |
| 3 | 每个值带 entity_id/signal_id | 握手期建**槽表**，运行期只传值 | 降低开销、避免重复解析 |
| 4 | 双缓冲为默认 | **锁步单缓冲 + step_id 握手**为默认；Async 保留 | 确定性优先，复杂度最低 |
| 5 | 模型与 Webots 的绑定 | 增加 **每实例一段**、report 区、`epoch` 复位机制 | 崩溃隔离、reset 后不错步 |
| 6 | 未规定多模型叠加 | 同对象同类作用量在 World 帧求和 | 多对多绑定需要明确语义 |
| 7 | 过期数据不得无限期施加 | 适配器显式清零（Motor.setTorque 会保持）、限幅、限变化率、连续失败转 Error | 把模型当不可信输入 |
| 8 | 坐标系"需统一" | 协议 World 固定为 ENU，适配器转换 | 模型不需要关心世界设定 |
| 9 | 同进程模式为首选 | 第一期仅独立进程 + 共享内存；同进程保留为可选 | 模型确定为独立进程 |
| 10 | 电气量可作为扩展域 | 电气量不进必需信号，留模型内部 | Webots 不消费电气量 |
| 11 | — | 新增 FMU Runner 接入路线（后续） | 开源模型通常可导出 FMU |
